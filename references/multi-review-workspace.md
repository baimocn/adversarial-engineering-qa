# 多模型多会话质检工作区

多路质检必须把“包身份”“唯一解包”和“每路输出”分开管理。目标是：一个包只解一次，所有模型只读同一份提取树；每个模型会话各自拥有唯一报告目录，不共享或覆盖报告文件。

## 1. 目录命名

使用：

```bash
python scripts/prepare_review_workspace.py prepare \
  --artifact "<待检包或目录>" \
  --task-id "<包任务编号>" \
  --package-version "<包版本，例如 v37>" \
  --model "<质检模型名>" \
  --session-id "<对话会话 ID，可省略自动生成>" \
  --root "<质检根目录>"
```

生成结构：

```text
<质检根>/
  <任务编号>__<包版本>__<包哈希前12位>/
    workspace.json
    extracted/                                   # 全局只允许解包一次
    reviews/
      <任务编号>__<包版本>__<模型名>__<会话ID>/
        run.json
        report.txt / report.md / report.json
        ...
```

命名规则：

- 工作区根：任务编号 + 包版本 + 完整包哈希前 12 位；
- 报告目录：任务编号 + 包版本 + 质检模型名 + 会话 ID；
- 同一模型的不同对话框必须使用不同会话 ID，不共用报告目录；
- 会话 ID 未提供时由脚本以 UTC 时间和随机后缀生成，避免“同一时间段两个对话”碰撞。

## 2. 只解一次

- `extracted/` 只能由 `prepare_review_workspace.py` 创建；
- 首个会话完成解包后，其他会话只复用并核验，不重新解压；
- 同时启动时用原子锁实现 single extraction；后启动者应等待首个释放锁后重试，不得各自解包；
- 解包先写临时 staging，校验后再原子替换为 `extracted/`，失败不留下半成品；
- 解包前检查越界路径、链接、特殊文件、文件数和解压后总大小。

## 3. 只读与漂移

所有质检的读取面固定为 `extracted/`。报告、底稿、脚本、缓存和临时文件只能写入本会话 `reviews/<当前目录>/`。

脚本保存提取树的：

- 文件总数；
- 总字节数；
- 全树按路径排序的 SHA-256 摘要。

每次复用及收尾执行：

```bash
python scripts/prepare_review_workspace.py verify \
  --workspace "<任务编号>__<包版本>__<哈希前12位>" \
  --out "<会话目录>/workspace-verification.json"
```

树内容变化、文件增加或删除时立即失败，不自动修复、不覆盖提取树。需要修复只能按新的包版本/哈希创建新工作区，并保留旧工作区作为证据。

## 4. 防路径继承

同一模型在多个对话中质检时，容易把前一个包的绝对路径、旧报告和旧判级带入下一轮。每个 `run.json` 必须重新绑定：

- 当前任务编号；
- 当前包版本；
- 当前完整 SHA-256；
- 当前 workspace manifest 的 SHA-256；
- 当前模型与会话 ID；
- 当前共享提取树的相对路径。

旧对话内容只能作为待检历史背景，不得作为本轮路径来源或判级依据。换包后必须新建工作区；即便文件名和目录名相同，也以完整哈希为准。

## 5. 并发与报告

- 每路只写自己的会话目录；禁止把最终报告写进共享根、`extracted/` 或其他模型目录；
- 汇总报告由指定主编排者在收到各会话报告后另行生成，不覆盖任一原报告；
- 各路先在会话目录内生成 `report.*`，主编排者只读引用这些报告；
- 同一模型多路是不同来源，不得把多次复述计为独立红队。

## 6. 与动态验证的关系

当前 Skill 默认静态只读；工作区同样禁止执行、导入或运行待检代码。后续引入 WSL2、Docker 和授权沙箱时，动态验证仍必须使用可丢弃副本、最小挂载和独立输出，不得改写共享 `extracted/`。
