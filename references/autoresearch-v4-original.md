## 占位符清单（使用前先填这几处）

| 占位符 | 含义 | 填法 |
| --- | --- | --- |
| `[[包路径]]` | 待检提交包（zip 或目录） | 绝对路径 |
| `[[包大小]]` / `[[sha256]]` | 包大小（bytes）与 sha256 | 用 `sha256sum` 核对后填 |
| `[[skill 路径]]` | 质检 skill 目录 | 默认 `D:\Desktop\论文质检\review_skill-0.3.10-standard-waiver.5_1023\autoresearch-task-qa-legacy-waiver` |
| `[[输出目录]]` | 本轮报告目录（必须在待检产物外） | 例如 `D:\Desktop\论文质检\qa_<编号>_round<N>` |
| `[[已知背景]]` | 平台上次判退原因、已知历史结论 | 没有就写"无"，不得留空 |
| `[[豁免白名单是否适用]]` | 是否属于本 skill 指定的历史旧题批次 | 填"适用（用 format-repair-policy.md 的 reason code）"或"不适用（不产生 pass_with_waivers）" |
| `[[判读队列文件]]` | 机器扫描产出的"待人工判读项"清单路径（闸门 4.10 用） | 质检方自行生成的 JSON/TSV，格式见闸门 4.10 |

## v3 增补：判读环节不可批量归因

> 本节**不改变原有六道闸门的编号、顺序与通过条件**，只在闸门内部增加子项、
> 在交付物中增加两张专项表、在收尾核验卡中增加三条。
>
> **增补动因（一次真实漏判，与 v2 的漏判性质不同）**：
> v2 针对的是"没设检查项"——本轮质检**设了全项机器扫描**，把出问题的数字
> （一个旧锚点口径的 reward 值）**明确打印进了"待判读"清单**，质检方也看见了，
> 却因为同一行/同表相邻行有"旧锚点"字样，就把它按类别一并归入
> "显式标注的旧值"，批量放过；随后又写下"未发现数值错误"这种无范围的否定结论。
> 该题的数值复算（80 个字段）、指纹重算、官方审计器**全部通过**。
>
> **因此 v3 针对的不是"查什么"，而是"查到了之后怎么落锤"**：
> 机器负责找，判读环节才是漏判发生的现场。v3 的增补全部用于
> **消除"按类别批量放过"的空间**，并强制暴露判读队列本身。

## v4 增补：声称的能力必须在自身产物中可达 + 类泛化纪律

> 本节**不改变原有六道闸门的编号、顺序与通过条件**，只在闸门内部增加子项、
> 在交付物中增加两张专项表、在收尾核验卡中增加两条、在禁止事项中增加三条。
>
> **增补动因（一次真实漏判，与 v2/v3 的漏判性质都不同）**：
> v2/v3 之后，文档归属（4.8）、表格口径（4.9）、判读落锤（4.10）、同表横看（4.11）
> **全部通过**，571 条判读队列 0 确认错误，数值复算 80/80、指纹重算一致。
> 但外部质检报告指出一处 QA21 未通过，复核后**成立**：
> 某"唯一最佳方法完整可运行代码"目录，其训练入口拟合出方法所需的校准矩阵后，
> **只写进 model.pt 的 meta 与 run_meta.json，未生成 inference.json**；
> 调用脚本训练后直接跑 Dev 评测，未生成也未传递该清单；
> 而评分契约规定**缺 inference.json 时按缺省单模型/单视图/恒等读出复算**。
> 于是按该目录自身代码跑一遍，Verifier 复算出的是单视图恒等结果，
> 而该目录的 README 声称的是"18 视图 TTA + 仿射校准"。
> 所声称的分数来自**另一个目录下单独交付的** inference.json，不是它自己跑出来的。
>
> **v4 因此补两类**：
> ① **可执行复现链核对**（4.12）：对每个"最佳方法 / 参考交付"目录，
>    必须追一遍 `训练入口保存语句 → 调用脚本 → 评分契约缺省行为` 的完整链，
>    确认声称的方法能力在**该目录自身产物**中可达。这是新检查类型。
> ② **类泛化纪律**（4.13）：v2/v3 的增补都是"上一个错"的精准补丁——
>    每加一条检查只扫引发该漏判的那个文件，不做类泛化，所以 v4 漏的错
>    不在任何一块旧补丁的射程内。v4 起强制类泛化。
>
> **v4 第二轮补全（穷举，不靠猜）**：初版 v4 仍只针对上述单一错误。
> 将两路质检对**同一个包**（AutoRe0823）的全部判定分歧逐条对齐后，共识别 8 处分歧
> 与 5 处本方独有漏判，穷举归入**错误类台账 E1–E14**（4.13(f)）：
> 落锤→判级断链（E7）、绑定声明无对应物（E8）、有效时长口径（E9）、可比性措辞过强（E10）、

> 每类落到明确检查位置：闸门 3 两条新规则、4.4.6、4.8(d) 三条新形态、4.10(a) 载体全覆盖、
> 4.12(g) 两条新形态、5.6 有效时长口径复核、核验卡 17/18、禁止事项与短追问同步扩充。

新增两条填表规则（v2）：

- **归属类 evidence 必须落到"被描述对象"上**：当某项的结论依赖某份说明文字
  （README / 专家作业说明 / reverify 结论 / 题面表格），evidence 不能只引该文件本身，
  必须同时引**该文字所描述的那个对象**（代码位置 / 配置文件 / 产物清单）。
  例：判"winner 可复算"时，若依据 README 的能力描述，须同时引 README 行号
  **与** `inference.json` / `train.py` / `run_meta.json` 中对应实现的证据。
  只引前者 → 该项最高 manual。
- **数值类 evidence 必须区分口径**：凡包内并存多套口径（当前锚点 / 旧锚点 /
  公开 Dev / 隐藏口径），引用的数值须注明取自哪套口径，且该口径须为当前生效口径。
  引用旧口径值而未标注 → 该项最高 manual；旧口径值与当前口径值共居一列未区分
  → 按闸门 5.5 判 fail（见下）。
- **本项的结论不得越过闸门 4.10 的落锤**：若本项结论依赖某个"机器已标出、
  待人工判读"的数值，而该数值尚未在闸门 4.10 的队列里取得 disposition，
  本项最高 manual。理由：工具标出 ≠ 质检方已核；曾发生机器明确标出、
  人工按类别批量放过、最终写下"未发现数值错误"的漏判。

新增一条填表规则（v4）：

- **能力类 evidence 必须追到"该目录自身产物"**：当某项结论依赖某目录/某轨
  声称的**方法能力**（多少视图、什么池化、什么读出、是否集成、能否复算），
  evidence 不能只引 README/run_meta 的文字描述，必须追到
  `训练入口的保存语句 → 调用脚本 → 评分契约在该缺省条件下的行为`，
  证明该能力在**该目录自身跑一遍的产物**中可达。
  例：判"某目录是 18 视图 TTA + 仿射校准"时，须确认其训练入口确实写出了
  携带该视图/读出配置的清单文件（如 inference.json），且调用脚本确实传递了它；
  若契约规定"缺该清单则按缺省单视图恒等读出复算"，而目录里没有该清单
  → 该项最高 manual，且须按闸门 4.12 判 fail。
  只引 README 与 run_meta → 该项最高 manual。
  理由：曾发生文档归属、口径、判读、数值、指纹**全部通过**，
  但"唯一最佳方法完整可运行代码"目录自身跑出来的却是缺省单视图结果，
  而 README 声称的是 18 视图 + 仿射校准——声称的能力未在自身产物中可达。

再补两条填表规则（v4 穷举补全）：

- **落锤→判级映射（E7）**：每项 status 的判定依据必须写明：本项与判读队列 /
  各专项表中的 `确认错误`、`无法判定`、`不可达`、口径 fail 各条**如何映射到本项判级**；
  声称"零影响"的，逐条给出映射依据（为何不影响本项）。存在未映射的确认错误
  → 本项最高 manual。
  理由：曾发生队列判出 2 处确认错误、报告如实列出，但全部 QA 项照常 pass 且
  无一处说明判级为何不受影响——**"进了报告"不等于"进了判定"**。
- **包内旧结论不沿用（E11）**：包内自带的旧质检结论与自校验结果
  （如"G02=manual 已获平台认可"、"官方 H06 校验器 pass"、verify_all ALL PASS）
  只能作为**待检对象**，不能作为本轮判级依据；须本轮独立复核后重新判级，
  并在判定依据中写明"未沿用包内 X 结论，本轮独立复核结果为 Y 及依据"。
  理由：曾发生一方沿用包内 G02=manual 标注判 manual，另一方重做 B01–B08
  专项复核后判 pass——**沿用即把上一轮的判级误差原样带入本轮**。

闸门 4：有效性字段 · 正式值 · 约束绕过面 · 资源合规（通用深挖，必须铁证）
本闸门不绑定具体题目：深挖目标由占位符 [[已知背景]] 提供；
本节所有表必须全包穷举，不得以"重点题"为借口漏 run 漏字段。

闸门 4.1 有效性字段溯源（不许只看 *_valid=true 就相信）
  在全包内搜索：baseline_valid / reference_valid / non_degenerate /
  reload_identical / quality_gate / *_passed / *_ok / valid / passed
  输出表：
  | 字段名 | 出现文件:行 | 值分布 | 生成它的代码(文件:行) | 独立交叉验证 | 结论 |
  对每个字段回答三问：
  Q1 这个值是什么、在哪些地方出现？
  Q2 它是算出来的还是写死的？贴生成代码行号；找不到任何生成逻辑 → 明确写"包内无生成逻辑"
  Q3 若全为 true，凭什么相信它成立？有没有独立原始指标可交叉验证
     （准确率、预测分布、loss 曲线、首步梯度范数等）？拿不出来 → 该字段判 unverifiable

闸门 4.2 正式值复现性（逐 run）
  逐个正式 run 的 result.json 主指标，用包内原始产物（pred 文件 + 标签 / 日志 /
  checkpoint 重载记录）独立复算。不得信任任何汇总文件、README 或作者自述。
  输出表：
  | run 路径 | 角色(B/R) | seed | 文档值 | 复算值 | 原始产物路径 | 一致? |
  复算不一致的正式值 → 默认 invalid（对应 paired_runs 的 *_valid=false），
  正式聚合不得采用该值；"作者已披露但未订正"不改变 invalid 判定，
  披露透明是诚信记录，不是有效性证明。无效值不得作为改善主张的正证。
  包内任何材料（含作者自己的说明、取证文件、README）与正式值冲突时，
  冲突本身即记入 finding；选择采信哪一方须给出可定位的原文依据。

闸门 4.3 约束绕过面枚举（题面声称 enforced / 上限 / 不可修改 / 不可绕过的，逐条填）
  | 约束 | 声明出处(文件:行) | 执行点(文件:行) | 输入控制方 | 覆盖通道 | 三路径推演 | 判定 |
  · 输入控制方：候选可控行 / 平台可控行（逐一注明：命令行参数、环境变量、
    可写文件、挂载点、配置文件）
  · 三路径推演：缺省值路径、显式覆盖路径、越界/非法值路径各一行结论
  · 任何一条覆盖通道候选可控且执行点无校验 → 对应项 fail，
    理由写"声明约束未被执行"，不接受"默认值正确"作为通过理由
  · 约束由题包提供的入口强制（包装脚本、只读目录）时，
    仍须检查该入口自身可否被绕过（环境变量、其他调用路径、直接调原始脚本）
  · 该表整体放入 report 的对应 QA 项 evidence；缺任何一列 → 该项最高 manual

闸门 4.4 资源与预算合规（逐 run 落表，不许抽样）
  4.4.1 从 task.toml / instruction.md 找显式声明的上限（显存/内存/时长/卡数），
        把原文那一行原样贴出，并说明该上限的约束对象（单轮？全流程？单角色？）
  4.4.2 对**每一个**正式 baseline / reference run 找实测峰值
        （搜索 peak / max / 峰值 / memory / 显存 / GB / wall_seconds / duration）
        输出表：
        | run 名称 | 角色(B/R) | seed | 声明值(出处) | 实测峰值(字段全名) | 是否 ≤ 上限 |
  4.4.3 任一 run 实测超限 → 该 run 判 invalid；若 invalid 的 run 被用于
        "正式主张" → 整个改善主张不成立，对应 G02/G03 判 fail
  4.4.4 若 invalid 的 run 只作"探索记录"且已明确标注 → 不判 fail，
        但必须确认该标注真实存在并贴出行号
  4.4.5 交叉验证：找出正式主张实际引用的是哪些 run 的哪些 result.json，
        与 4.4.2 的表逐一对上；引用了超限 run → 正式主张无效
  4.4.6 (v4) 估算口径（E13）：单轮资源/时长估算必须按**最坏合规路径**取值
        （最大合法成员×视图的复算成本、目标卡性能未知时的保守系数、
        训练+产物推理+Dev 评测全阶段），不得以历史最优实测 run 直接当单轮预算结论；
        估算锚点必须是"当前可提交方法"，历史高成本探索方案（如 31 模型集成）
        只能单列为"未采用方案"，不得作为估算依据或预算反证。
        理由：曾发生一方按最优实测估约 300s，另一方按最坏合规路径保守估算 6600s
        并指明 31 模型历史方案不可作锚——两个数都低于上限，但口径不同，结论强度不同。

闸门 4.5 同口径同预算内的真实效果（关键，最易被高分掩盖）
  - 找出所有**合规预算内、口径相同、seed 可配对**的 B/R 结果
  - 复算它们的 σ_B 倍数（样本标准差，n−1）与归一化分数（Δ/abs(U−B均值)）
  - 与门槛比对：归一化 ∈ [0.15, 0.8]；改善 ≥ 3σ_B（3–5σ 可接受并建议复核，
    ≥5σ 为强证据）
  - **如果合规区间内未达门槛，必须如实报告，不许用超预算的高分掩盖**
  - 明确写："合规区间内最强成对结果为 X σ_B / 归一化 Y，未达/已达门槛"

闸门 4.6 派生数重算（文档与 JSON 中所有派生数一律代码重算）
  均值 / 标准差 / Δ / σ 倍数 / 归一化 / 占比 / 换算，全部与原始值逐项核对，
  容差仅限展示舍入。输出差异清单：
  | 文件 | 字段/行 | 应得值 | 文档值 | 是否影响门槛 |
  "历史口径留档"与"生效字段残留"分开列；生效字段残留逐条要求订正。

闸门 4.7 废止/更正声明核验
  凡底稿或作者材料声称某约束/字段/口径"已废止、已更正、已迁移"：
  1. 必须同时给出三方原文：旧版原文（含出处与版本）、现行版原文（含出处）、
     变更发生位置的注释或修订记录；
  2. 三方任一缺失，或现行文件之间存在注释与正文冲突 → 该前提记 manual，
     在报告中并列呈现冲突原文，不许择一采信；
  3. 废止的约束不等于"无约束"：须核对新口径下约束由谁执行、如何执行；
     "删字段"只解决配置兼容，不证明约束已落实或题目仍成立。

闸门 4.8 说明层归属核对（v2 新增；专防"数值全对、归属全错"）
  适用范围：题包内一切**描述能力、边界、缺口、限制、失败原因、可复算性**的文字载体
  （各 README、专家作业说明、reverify 结论、best_selection、题面表格与题面正文）。
  这些文字不参与数值计算，因此逐位复算对它们完全无感，必须逐条人工对应。

  操作步骤：
  (a) 全包扫描上述载体，抽出全部"能力 / 边界 / 缺口 / 限制 / 失败原因 / 可复算性"
      类声明，每条编号（A1、A2…）。**负面声明优先**（限制、缺口、未落盘、
      不可复算、失败原因），这类最易被误植。
  (b) 每条声明填表：
      | 编号 | 声明原文(文件:行) | 声明所属对象(哪个轨/哪个目录/哪个角色) | 被描述对象的实际实现证据(文件:行) | 归属判定 |
  (c) 归属判定只允许三种：
      · 一致 —— 文字描述的对象与实现证据指向同一对象
      · 误植 —— 文字描述的是 A，实现证据显示该性质属于 B（**记 fail**）
      · 无法确认 —— 找不到对应实现或找不到对应文字（**记 manual**）
  (d) 高频误植模式（遇到即重点核对，不得因"数值没问题"跳过）：
      · 把 A 轨的缺口（权重未落盘 / 成员只保存一部分 / 配置不可复现）
        写进 B 轨或 winner 目录的"已知边界"
      · 把"本目录是单模型 + TTA"与"多成员集成"两种形态混写
      · 把某轮的过程记录写成最终提交，或反之
      · 把探索性 / 历史口径的数字写进"当前生效"结论段
      · (v4/E8) 说明层记录的源码/清单 SHA（或"包内某文件即该版本"类声明）
        在包内**穷举哈希后找不到对应文件**，或与被指文件不一致——
        仅以"该 SHA 不用于绑定"类自述放行不算核对；找不到对应物
        → 该条记 manual/无法确认
      · (v4/E8) 归档文件名/目录名携带语义断言（wrong_version、superseded、
        deprecated、old 等）与该文件实际内容或现行用途矛盾
        （如名为 wrong_version 的文件与现行交付版逐字节相同）且包内无解释
        ——属归属类声明，须按 (b)(c) 判定
      · (v4/E10) 两轨条件比较的结论措辞只能写"未发现实质差异 + 证据缺口
        （列明缺失原件）"，不得写"same_conditions / 已证明同条件"；
        共享 Prompt 模板/启动原件未随包交付时，必须显式列为证据缺口
  (e) 该表整体放入 report.json 的 `attribution_review` 字段，并作为 QA21 / QA18 /
      QA03 / QA13 / G02 的补充 evidence。有任何一条判"误植" → QA21 直接 fail，
      不得以历史迁移缺口豁免（历史白名单只覆盖 hash/版本绑定迁移，
      不覆盖"说明与实现不符"）。

闸门 4.9 口径一致性矩阵（v2 新增；专防"旧口径值放进当前口径列"）
  适用范围：题包内一切呈现数值的表格与单元格（专家说明的跑分表、复验表、
  comparison_summary、expert_annotation、题面表格、README 结论段）。

  操作步骤：
  (a) 先列出本题实际并存的全部口径，及每套口径的**当前生效性**：
      | 口径名 | 定义(锚点/数据集/seed 集) | 出处(文件:行) | 当前是否生效 | 判定依据 |
      典型并存：当前隐藏口径 / 旧锚点口径 / 公开 Dev 口径 / 早期探索口径。
  (b) 对每个呈现数值的单元格填表：
      | 单元格(文件:行) | 呈现值 | 所属列/段声称的口径 | 该口径下应得值(复算) | 一致? |
      复算一律用当前生效口径；旧口径值只允许单独成列或紧邻明确标注。
  (c) 判定规则：
      · 单元格未显式标注口径，且其值 ≠ 当前生效口径应得值
        → 记 fail（"当前口径位填入了非当前口径值"）
      · 单元格已明确标注为旧口径且注明"仅留档"
        → 记 pass，但须在报告中列出该标注的行号
      · 附近有注文说明旧口径、但单元格本身未标注且与当前口径不符
        → **仍记 fail**。注文不能替代单元格标注：看表的人读的是单元格。
        （"披露透明是诚信记录，不是有效性证明"）
  (d) 该表整体放入 report.json 的 `caliber_review` 字段，并作为 QA02 / QA21 的
      补充 evidence。

闸门 4.10 判读队列逐条落锤（v3 新增；专防"机器已标出、人工批量放过"）
  适用范围：闸门 4.1–4.9 过程中由**机器扫描产出**的一切"待人工判读项"。
  这些项已被工具标记为"无法自动判定"，因此**判读环节是唯一的判定点**，
  也是漏判的实际发生地（曾发生一次：工具把一个旧锚点口径的 reward 明确打印进
  待判读清单，质检方因同表相邻行有"旧锚点"字样而按类别批量放过，
  随后写下"未发现数值错误"的无范围否定结论）。

  (a) 判读队列必须**落盘为文件**（[[判读队列文件]]），不得只在对话里看过就算。
      每条至少含：队列号、文件:行、原文片段、抽取到的数值、机器给出的候选基准。
      (v4/E12) 扫描载体必须**声明并覆盖全部文本类型**：md/json 之外，
      .log / .tsv / .txt 等日志与表格文件至少做断言行级扫描
      （含 reward / score / accuracy / acc / σ / Δ / acc 关键字的行）；
      报告须**分文件类型**给出扫描条数与逐条判读条数。
      扫描范围本身是判定变量：曾有两轮质检对同一包分别扫出 571 条与 7827 条——
      范围不同，射程不同，只报总数不报类型分布视为未声明。
  (b) 队列中每一条都必须有 disposition，且**只允许这四种**：
      | disposition | 必填 | 含义 |
      |---|---|---|
      | `确认正确` | 复算值 + 比对依据 | 该值经独立复算与文档一致 |
      | `确认无关` | **该行/该段的逐字特征** | 该值不是有效断言（哈希、字节数、行号…） |
      | `确认错误` | 应得值 + 差异说明 | 该值与应得值不符 |
      | `无法判定` | 缺什么证据 | 证据不足 |
      严禁第五种。**"其他/明显无关/无意义"等写法一律不收**——
      批量归因的入口就是这种逃生舱。
  (c) `确认无关` 的逐字特征必须**可机器复核**，且只能取以下之一：
      · 该数字匹配包内某个哈希前缀 / 文件字节数 / 行号 / 时间戳 / 版本号
        （须写明是哪一类，并给出该类判定规则）
      · 该数字所在整段属于被**显式标注为历史/旧/留档**的区块，
        且**该数字本身落在被标注的区块内**
      凡是"看起来像"某一类而无法逐字验证 → 只能判 `确认无关` 之外的
      `无法判定` 或 `确认错误`，**不得**判 `确认无关`。
  (d) **禁止行间借光**：同一行/同一单元格是否"已被标注为旧值"，
      只能依据**该行/该单元格自身**的标注。
      邻行、同表其他行、上下文的注文**一律不构成**该行可豁免的依据。
      （曾发生的正是此错：winner 行未标口径，却因相邻 seed 行标了"旧锚点"而被放过）
  (e) 队列中每条 `确认错误` 或 `无法判定` 都必须**写进最终报告**，
      不得只留底稿。队列本身作为交付物（见闸门 6.1 `judgement_queue.json`）。
  (f) 本闸门的完成判据：队列条目数 = 已 disposition 条目数。
      有一条没落锤 → 本闸门未完成 → 后续闸门不得开始。

闸门 4.11 同表横看：禁止行间借光（v3 新增；与 4.10(d) 配套）
  适用范围：题包内**一切并排呈现多个对象的表格**——跑分表、复验表、
  候选对比表、多轨对照表、锚点对照表。

  操作步骤：
  (a) 对每张此类表，先写出"**该表并排了哪些对象**"（轨与轨、角色与角色、
      候选与候选、旧与新）。表格的比较单位是**列/行所代表的对象**，不是单元格。
  (b) 对每一组并排对象，逐项检查它们的**口径是否一致**：
      锚点、指标方向、数据集、seed 集、评估入口、判定规则。
      任一不同 → 该行须**在单元格内**标注口径，否则记 fail（闸门 4.9(c)）。
  (c) 关键自问（必须逐张表回答，不能跳）：
      · 这张表里有没有哪个单元格，用的是**另一套口径的值**，而它自己没标？
      · 这张表里有没有哪个单元格**描述错了归属**（把 A 的性质写到 B 名下）？
      · 表头写的对象名，与该行数值实际来自的对象，是同一个吗？
  (d) 输出一张"**表内对象 × 口径**"对照矩阵，每格写"同/异 + 依据"。
      该矩阵放入 report.json 的 `table_object_caliber_matrix` 字段。
  (e) 只在单对象表（不并排任何对象）上，才可省略 (b)(c)。

闸门 4.12 可执行复现链核对（v4 新增；专防"文档全对、自身跑不出来"）
  适用范围：题包内一切被定位为**最佳方法 / 参考交付 / 唯一可运行代码**的目录
  （如 best_method/、reference/、winner 目录、reverify 的复验产物目录）。
  这些目录的定位是"完整可运行代码"，因此**其自身产物必须能复现它声称的方法**。

  操作步骤：
  (a) 列出每个此类目录声称的方法能力（视图数、池化方式、读出类型、是否多成员集成、
      校准矩阵、TTA 配置等），逐条编号（R1、R2…）。
  (b) 对每条能力，追完整链并填表：
      | 编号 | 声称的能力(文件:行) | 训练入口保存语句(文件:行) | 调用脚本是否传递(文件:行) | 评分契约在缺该配置时的行为(文件:行) | 该目录自身产物是否含该配置 | 可达判定 |
  (c) 可达判定只允许两种：
      · 可达 —— 该目录自身跑一遍的产物中，确实携带并使能该能力
      · **不可达 —— 记 fail**。典型形态：能力只写进 meta/run_meta 等**元数据**，
        未生成评分契约要求的**推理清单**（如 inference.json）；或调用脚本训练后
        直接跑 Dev 评测，未生成也未传递该清单；而契约规定缺清单时按缺省
        单模型/单视图/恒等读出复算。
  (d) **必须查契约的缺省分支**：找到评分契约中"缺某配置时怎么办"的代码，
      原样贴出那几行。缺省行为是"单视图恒等读出"这类降级时，
      声称的多视图/校准能力在该目录自身产物中即为不可达。
  (e) **区分"自身产物可达"与"别处单独交付"**：若该能力实际由另一目录下单独交付的
      清单（如 reverify/.../inference.json）实现，而本目录自身没有，
      仍记**不可达**——因为本目录的定位是"完整可运行代码"，
      "分数来自别处的清单"不构成本目录自身可复现。
  (f) 该表整体放入 report.json 的 `reproducibility_chain_review` 字段，
      并作为 QA21 / QA03 / QA13 / QA18 的补充 evidence。
      任何一条判"不可达" → QA21 直接 fail，不得以历史迁移缺口豁免。
  (g) 常见易漏形态（遇到必查）：
      · 校准矩阵/权重只进 `model.pt` 的 `meta` 或 `run_meta.json`，未进推理清单
      · 训练脚本 `torch.save` 只保存 `models[0]`（多成员集成只落盘首成员），
        而预测由全体成员产生
      · 调用脚本训练后直接调 Dev 评测，中间没有生成/传递清单的步骤
      · README 声称的能力在该目录的 `--help`/参数默认值里根本不存在
      · (v4/E14) 推理清单必须由**本次运行的产物**生成：清单中的校准矩阵/
        checkpoint 引用须对应本次产物；从旧 checkpoint 盲复制矩阵
        → 本次重训后清单与产物不一致，仍判不可达
      · (v4) 同名参数在训练侧与推理侧语义不同（如训练先验系数 vs
        推理校准初始化）且文档未区分——属能力描述不完整，记 manual 并要求补文档

5.1 表格算术
  - 找出包内所有多列数值表格（| a / b | c / d | Δ | 这类）
  - 每行代码复算：Δ = (c+d)/2 - (a+b)/2，比值，均值，标准差
  - 与文档写的值比对，容差 0.005
  - 报出所有差异：文件:行 + 应得值 + 文档值

5.2 三门数值复算
  G01：优化面是否真实开放（读 Allowed Scope / guard / 接口实际执行边界，
       不是看文件名或"允许算法优化"口号）
  G02：Baseline 是否健康、同预算、同数据对照、全部 seed 披露
       （五维：training_sufficiency / method_representativeness /
        budget_comparability / implementation_correctness / selection_integrity）
  G03：逐 seed 复算 Δ、σ_B、归一化，与门槛比对；
       明确 direction（minimize/maximize）与 evaluation_mode（stochastic/deterministic）；
       不得用标准误、配对差标准差或 Reference 方差替代 σ_B

5.3 结论字段
  - 打开终稿 report.json（[[输出目录]]/report.json），读 decision 字段，原样报给我，
    不许改写措辞
  - 注意两层脚本的取值不同，别报错文件：
    · 原标准层（standard_review/report.json）：PASS / FAIL / INCOMPLETE
    · 豁免层（waiver_review/report.json）：PASS_WITH_WAIVERS / FAIL / ERROR
  - decision ≠ PASS 时不得说"通过"；PASS_WITH_WAIVERS 只能说"带豁免通过"，
    且必须逐项列出豁免前原判、豁免原因编号、豁免后仍保留的事实

5.4 豁免处置（仅当占位符声明豁免白名单适用）
  - 白名单只作用于某项中的具体 finding，不直接把整条 QA/H/G 变成通过
  - 每个 finding 保留原始事实、证据与原判；填具体 reason code
    （见 references/format-repair-policy.md 的逐原因豁免白名单表），
    不能只写"旧题已豁免"
  - 同项其他未豁免问题继续生效；一条总豁免不得覆盖全部原失败
  - QA17 不能整行申请豁免，须由 H01–H06 逐原因结果派生

5.5 表格口径与归属复核（v2 新增；5.1 的"表格算术"之后必须再过一遍）
  5.1 已复算"算术对不对"，本节复算"这个数该不该出现在这个位置"：
  - 对 5.1 找出的每张多列数值表，逐列标注其声称口径，并用当前生效口径复算该列
    应有值；不一致 → 按闸门 4.9(c) 判 fail
  - 对 5.1 找出的每张表，核对表头归属（哪一轨 / 哪个角色 / 哪个目录），
    与该行文字描述的实现证据对应；不一致 → 按闸门 4.8(c) 判 fail
  - 报出所有差异：文件:行 + 应有值/应有归属 + 实际呈现
  本节与 4.8 / 4.9 共用同一份底稿，不重复建表。

5.6 有效时长口径复核（v4 新增；专防"墙钟窗口=有效时长"，E9）
  - QA16 判级不得把墙钟跨度、逐轮窗口合计或聚合窗口直接认定为"有效研究时长"
  - 必须给出内部时段分类：排队 / 安装 / 构建 / 故障 / 空转 / API 失联 / 行政收集，

    "未分类 N 秒，扣除不可知"，并把 QA16 原判保持 manual（走豁免），不得直接 pass
  - 窗口合计与墙钟跨度的差额要逐秒解释（如 37829 vs 37831 的 2 秒差；
    "末段 N 秒未新增轨迹行"类说明要核对轨迹行数前后值）
