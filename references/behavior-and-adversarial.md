# 行为覆盖与有效反例

## 1. 行为覆盖矩阵

对每个公开接口或关键内部契约建立一行：

| 字段 | 必填内容 |
|---|---|
| 接口 | 命令、函数、HTTP 路由、脚本或配置入口 |
| 声明 | 文档/题面中的原始承诺及位置 |
| 分支 | 正常、异常、超时、非法输入、空输入、边界、降级 |
| 调用契约 | 参数、返回数量/类型、退出码、输出文件、异常 |
| 环境 | cwd、布局、依赖、权限、网络、资源限制 |
| 证据 | 原样命令、退出码、日志、输出文件、静态推导 |
| 未覆盖 | 没跑到的分支及原因 |

测试名存在不等于行为被覆盖。每个分支必须有到达证据。

## 2. 声明命令的原样执行协议

1. 从声明中复制完整命令，不改参数、不补路径、不换等价入口。
2. 按 Dockerfile、安装脚本和文档重建声明布局。
3. 对每个合理 cwd 分别记录；若文档指定 cwd，以其为准，其他 cwd 只作补充。
4. 记录命令原文、cwd、环境、退出码、stdout/stderr 和生成物。
5. 不用预置缓存、旧结果、隐藏依赖或人工创建声明外文件来“修复”运行。
6. 若原命令失败，再用修正命令诊断根因；修正命令成功不能反证原命令正确。

## 3. 返回与异常契约

对每个跨函数边界检查：

- 所有返回分支的数量、顺序、类型和可空值是否一致；
- 调用方解包数量、字段访问和异常处理是否覆盖所有返回形态；
- 超时、异常、取消、部分结果是否走同一契约；
- 错误是否被转换成约定的失败结果，还是在到达约定路径前崩溃；
- 配置键、环境变量、输出文件名在 producer/consumer/docs 是否同义同形。

静态扫描发现候选后必须打开定义和调用点核对。动态类型、反射和无法解析的返回记为覆盖限制。

## 4. 反例的两阶段判定

### 阶段 A：到达目标

必须提供目标内观测，例如目标函数中的标记、特定系统调用、受控文件访问、特定日志或桩调用。以下只算目标前失败：

- `SyntaxError` / `IndentationError`；
- import 失败、依赖缺失；
- 数据加载或无关初始化崩溃；
- 目标逻辑前超时；
- 攻击 payload 实际未被解析或执行。

未到达目标时，用例为无效反例，相关防御最高 `manual`。

### 阶段 B：防御有效

到达目标后，oracle 必须检查目标性质，例如秘密未被读取、外部文件未被写出、评分未被改变、约束确实拒绝非法值。通用 `exit != 0`、`reward=-1` 或“任务失败”不是充分 oracle。

## 5. 对照与 ablation

- **正对照**：无防御或替换防御时，攻击应能到达并产生可观察结果。
- **负对照**：合法行为在防御开启时仍按契约工作。
- **ablation**：移除/替换核心防护后重跑同一 payload，记录结果是否按预期改变。
- 对照环境除防御变量外保持一致；否则只能记为线索。

核心安全声明没有 ablation 时，不得给 EV4。

## 6. 隔离语义分栏审查

分别回答，禁止混写：

| 机制 | 实际提供 | 不自动提供 |
|---|---|---|
| Agent/Verifier 环境分离 | 两个运行环境 | 候选代码进入 Verifier 后的文件权限边界 |
| `python -I` | 隔离 Python 搜索路径和部分环境变量 | 文件系统、网络、UID 权限隔离 |
| 独立进程组 | 信号和进程生命周期管理 | 文件系统或网络隔离 |
| 容器 | 命名空间视图隔离，取决于配置 | 自动只读挂载、非特权 UID、禁网 |
| 文件权限/只读挂载 | 文件访问边界 | 网络或进程权限边界 |
| 网络命名空间/策略 | 网络访问边界 | 文件系统边界 |

候选代码若被移交到含 Hidden 的环境执行，威胁模型必须包含该阶段，不能只说 Agent 环境没有 Hidden。

## 7. NOP、早退和历史运行

记录 NOP 实际到达的阶段、处理样本数、命中分支和未命中分支。缺权重、空数据、`n_test=0`、提前 `reward=-1` 不能证明候选推理超时、评分写出或攻击防护路径。

历史运行只有在对象哈希、代码、配置、环境和命令均可绑定时才可作辅助证据；本轮关键声明仍需独立复核。

## 8. 动态安全边界

只运行用户明确授权的用例。优先使用合成秘密、临时目录和可丢弃环境；不读取真实个人秘密，不对外扫描，不连接未授权服务。反例用于证明边界，不用于保留或传播真实敏感数据。
