# 难度过低（短时间达峰）｜64题

**问题：**Seed在首版或第二版实质方案中，较短时间内即逼近已见最高合法分或理论上限，后续迭代增益有限；部分题目的研究空间退化为小型枚举、查表或固定参数。

**已有返修方向：**扩大问题规模或有效算法空间，消除闭式捷径及查表路径，增加能够区分方法的约束。仅延长轨迹或调整归一化刻度，不能解决研究空间过窄的问题。



# 难度过高／无高分合法解｜31题

**问题：**原报告按三轨最高分及Reference归一化得分均不超过0.20等条件筛查，涉及评分锚点失配、质量门无法稳定通过、优化空间不足等不同根因。

**已明确口径：**经沟通，按此前向专家同步的**0.15–0.8**口径处理；此前仅因0.15与0.20下限差异被打回的题目，可通过难度项。低于0.15的情况不在此次口径澄清范围内。



# 失败写成普通0分｜38题

**问题：**评分器在判题前预写0，或在格式错误、无效候选、候选超时、执行异常等分支仍发布0.0，导致失败结果与合法Starter水平混淆。

**已有返修方向：**统一错误分类及结果出口。候选违规、格式错误和候选超时等返回确定负分（报告要求≤−1）；0.0仅表示合法Starter水平。可信运行环境故障保留独立错误／无分诊断，不用普通0分代替。

# Verifier低效／预算失配｜11题

**问题：**独立case或训练串行执行，单次Verifier耗时过长；部分GPU任务资源配置不正确，或单seed预算、固定训练协议与声明时限不匹配。

**已有返修方向：**并行化独立case，修正GPU资源配置，按实际训练成本调整单seed预算及整体评测协议，并验证完整Verifier可以在声明资源和时限内完成。

**这部分在和算法沟通申请豁免**

# 评分门／合同与防作弊｜31题

**问题：**题面未公开实际评分约束，公开Dev与Hidden行为不一致，评分器误拒合法实现，资源探针不兼容，或公开环境泄露结果表、计时过程存在可回放漏洞。

**已有返修方向：**同步公开合同与实际评分规则，修正误拒的白名单或guard；修复资源探针兼容性；移除私有评测结果泄露，隔离计时状态及正式输入。修改后需复核合法实现可以通过，违规路径被正确拒绝。
